# Conventional Commits 参考

```text
type(scope)!: 中文主题

可选正文

可选 footer
```

scope 和 `!` 按需使用。

| type | 主要目的 |
| --- | --- |
| feat | 新增用户或调用方可用的能力 |
| fix | 修复不符合预期的行为 |
| refactor | 保持外部行为的结构调整 |
| perf | 有依据的性能优化 |
| docs | 只修改说明、文档或注释 |
| style | 不改变行为的格式调整；不是界面视觉改动的统称 |
| test | 测试及其辅助代码 |
| build | 构建系统或依赖管理 |
| ci | 持续集成配置与脚本 |
| chore | 其他维护，例如忽略规则和本地工具配置 |

优先匹配改动目的与仓库惯例，而非按文件后缀分类。普通依赖更新可依惯例采用 `build(deps)` 或 `chore(deps)`；修复依赖导致的实际缺陷也可能采用 `fix(deps)`。

例如：

```text
chore(git): 忽略 IDE 项目配置

停止跟踪本地 IDE 配置，避免后续提交环境相关文件。
```

```text
fix(order): 修复分页总数包含已删除订单的问题

统计与列表查询使用一致的删除状态过滤条件，避免出现空页。
```

破坏性变更的正文需说明影响和迁移方式；只有已存在并确认相关的 issue 才添加关联。提交正文不包含未执行的检查结论。
